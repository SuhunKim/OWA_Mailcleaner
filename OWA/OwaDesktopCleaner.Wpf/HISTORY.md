# WPF 메일 클리너 작업 및 검증 이력

## 2026-10-22 — 1.1.1 앱 내 사용 방법 추가

- 메인 화면 우측 상단의 `?` 버튼 또는 F1으로 여는 WPF 도움말 창을 추가했습니다. 도움말을 열어둔 채 메인 화면을 조작할 수 있으며, 중복 창은 만들지 않습니다.
- 연결 준비, 읽음 처리, 일반 첨부 삭제, 휴지통 이동, 휴지통 정리, 조회·선택·정렬·중단, 연결 실패 진단의 클릭·입력 순서를 설명합니다.
- 첨부 삭제 대상과 보존 대상, 최종 확인, 조건 변경 후 재검색, 결과 미확인 시 자동 재시도 금지 등을 실제 구현 기준으로 안내합니다.
- 도움말은 정적 XAML/C#이며 계정·설정·서버에 접근하지 않습니다. 실제 메일 변경 기능에 대한 사용자 검증 범위는 아래 기록과 동일합니다.
- 검증: Debug/Release 경고 0·오류 0. 실제 WPF 모의 UI에서 도움말 열기·닫기·재열기·중복 방지, F1 바인딩, 최소 크기 닫기 버튼과 스크롤 화면을 확인했습니다. ZIP 압축 해제본과 단일 EXE의 창 초기화 및 포함 런타임 사용도 확인했습니다.
- 배포 위치: `_bin\Deploy\2026-10-22-v1.1.1-help\Packages` — 단일 EXE 66.17 MB, 폴더형 ZIP 63.95 MB. 이전 배포본은 보존했습니다.

## 2026-10-22 — 단일 EXE 사용자 시험 결과

- 사용자가 단일 실행파일 시험을 완료했고, 실제 메일 **읽음 처리까지 정상 동작**함을 확인했다고 보고했습니다.
- 실행뿐 아니라 인증·메일 조회·대상 선택을 거쳐 읽음 처리를 수행한 경로가 사용자 시험으로 확인됐습니다. 에이전트가 실제 사서함 변경을 대신 시험한 것은 아닙니다.
- 일반 첨부 삭제, 휴지통 이동, 휴지통 정리는 시험할 사례가 없어 아직 확인하지 않았습니다. 실패한 것으로 분류하지 않습니다.
- 시험한 PC의 상세 네트워크 조건(외부망·VPN 여부 등), 계정 형식, 파일 해시 대조 결과는 별도로 수집하지 않았습니다. 모든 PC·회사 정책에서 접속이 보장된다는 의미는 아닙니다.

| 확인 항목 | 현재 상태 | 근거 |
|---|---|---|
| 단일 EXE 실행 | 사용자 확인 | 단일 실행파일 테스트 완료 보고 |
| 인증·메일 조회·선택·읽음 처리 경로 | 사용자 확인 | 실제 읽음 처리까지 성공 보고 |
| 일반 첨부 삭제 | 실제 사서함 미검증 | 시험 사례 없음 |
| 휴지통 이동 | 실제 사서함 미검증 | 시험 사례 없음 |
| 휴지통 정리 (SoftDelete) | 실제 사서함 미검증 | 시험 사례 없음 |
| 폴더형 ZIP의 다른 PC 사용 | 사용자 확인 전 | 로컬 압축 해제·실행 검증만 수행 |
| 다른 PC에서 .NET 미설치 상태 실행 | 별도 환경 확인 전 | 로컬에서는 배포본에 포함된 런타임 사용을 확인 |

## 2026-10-22 — 1.1.0 연결 개선 및 배포

- 다른 PC에서 OWA는 열리지만 WPF 연결은 실패한다는 보고를 받아 연결 진단을 추가했습니다. 당시 오류는 네트워크·TLS 공통 문구였으며, 최초 실패 원인은 특정되지 않았습니다.
- 회사 계정 직접 입력 안내와 `도메인\계정` 분리 처리를 보완했습니다. Windows 계정 연결과 직접 입력 계정 연결을 구분합니다.
- DNS·연결·TLS·프록시·인증 협상·HTTP·SOAP 오류 분류, 익명 서버 연결 진단, 진단 정보 복사를 추가했습니다.
- 공유 진단에는 버전·고정 오류 코드·HTTP 상태·허용된 인증 방식·Windows 오류 코드 등을 포함하고, 비밀번호·토큰·쿠키·메일 내용·사용자 이름·서버 응답 원문은 제외했습니다.
- TLS 인증서 검증, 리디렉션 차단, Negotiate/NTLM 인증 제한과 기존 변경 안전장치를 유지했습니다. JavaScript/WebView2 로그인 의존성은 추가하지 않았습니다.
- Debug/Release 빌드 경고 0·오류 0, 서비스/ViewModel 모의 테스트 44개, 연결 모의 테스트 20개가 통과했습니다.
- 실제 WPF 창의 모의 UI 검사와 ZIP 압축 해제본·단일 EXE의 창 초기화 및 포함 런타임 사용을 확인했습니다.
- 로컬 익명 EWS 진단에서 HTTP 401 및 Negotiate/NTLM 요구를 확인했습니다. 이는 외부 PC 인증 성공 검증과 구분합니다.

## 남은 확인

- 사용자가 지정한 시험 메일과 작업으로 일반 첨부 삭제·휴지통 이동·휴지통 정리를 별도 검증합니다. 에이전트가 실제 메일 변경을 임의로 시험하지 않습니다.
