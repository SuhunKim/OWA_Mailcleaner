# 회사 메일 클리너 — 데스크톱 구현

WPF + WebView2 데스크톱 앱. 기존 v1.1 기능을 cleaner.js로 분리 복사해 실제 OWA 문서 안에서 실행한다. 확장 프로그램, Tampermonkey, 설치된 Outlook은 필요 없다. 기존 v1.1과 OwaDesktopProbe는 변경하지 않았다.

## 실행

개발 환경: .NET 10 SDK + WebView2 SDK NuGet 복원.
프로젝트 폴더에서 dotnet build -c Release 후 bin/Release/net10.0-windows/OwaDesktopCleaner.exe 실행.
실행 PC에는 .NET 10 Windows Desktop Runtime과 WebView2 Runtime이 필요하다.
이번 작업에서는 설치 프로그램/배포 ZIP/자동 업데이트를 만들거나 사용자 PC에 배포하지 않는다.

## 흐름

1. 실제 회사 OWA 화면에 직접 로그인.
2. 상단 로그인 완료 · 클리너 열기. 필요 시 앱의 EWS 로그인 창에 같은 계정 입력. 이 PC에 저장을 선택하면 다음 인증 창에 사용자 이름과 마스킹된 비밀번호가 채워진다. 로그인 버튼으로 직접 확인한다.
3. 조회만 모드로 폴더·제목·기간 검색. 결과는 기본 선택 해제 상태다.
4. 변경이 필요할 때만 상단 변경 작업 허용을 선택하고 사서함 확인. 작업 모드를 바꾼 후 다시 검색·선택·실행 확인.
5. 인증 만료/거부 시 선택과 실행 권한을 무효화하고 재로그인. 변경 요청 자동 재전송 없음.

## 구현한 기능

- 폴더 경로, 제목·KST 기간 검색, 읽음/첨부 여부 필터, 휴지통 전용 검색.
- 개별·전체 선택/해제, 날짜·용량 정렬, 미확인 크기 표시, 합계 용량.
- 일반 첨부 삭제. 실행 직전에 재조회하고 선택 당시 첨부 ID와 교집합만 처리. 인라인/ContentId/ContentLocation 표시 및 파일 아닌 첨부는 보존.
- 읽음 처리(SaveOnly, SuppressReadReceipts), 삭제된 항목으로 이동, 휴지통 SoftDelete.
- 순차 처리, 중단 요청, 항목별 성공/실패/건너뜀/결과 미확인/미처리 보고. 불명확한 변경 결과를 재시도하지 않고 중단.
- 변경 직전 동일 메일 ID·부모 폴더·메일 클래스 및 최신 ChangeKey 재조회.
- native와 JavaScript 양쪽의 읽기 전용 차단, 알려진 EWS operation만 허용.

## 세션과 인증

프로필은 %LOCALAPPDATA%/OwaDesktopCleaner/profiles 아래에 앱 전용으로 생성한다.
OWA 로그인 기억을 기본으로 켠다. WebView2 비밀번호 저장 제안을 활성화하고 정상 종료 시 전용 프로필 ID를 저장하여 다음 실행에 재사용한다. 기존에 기억을 끈 경우 설정을 유지한다. 비밀번호 저장은 회사 로그인 후 WebView2 저장 제안에서 사용자가 선택한다.
OWA 입력값이나 기존 브라우저 인증 정보는 읽지 않는다. 사용자가 EWS 창에 입력한 비밀번호는 앱이 WebView2 인증 응답에 전달하며, 소스·로그·설정 파일에 기록하지 않는다. 이 PC에 저장을 선택한 경우에만 현재 Windows 사용자의 자격 증명 관리자에 앱 전용 항목으로 저장한다. WebView2 자체 세션 데이터는 전용 프로필에 있을 수 있다.
로그아웃은 사이트 데이터 정리 후 다른 새 프로필로 전환하여 HTTP 인증 캐시 재사용을 피한다. 회사 전체 SSO 로그아웃은 아니다.
강제 종료 시 정리는 보장하지 못하지만 다음 기본 실행은 새 프로필을 사용한다. 오래된 프로필 폴더는 남을 수 있다.
동시 실행은 한 인스턴스로 제한한다. 기존 검증 앱 프로필과 공유하지 않는다.

## 범위와 검증

구현 후 로컬 테스트/빌드를 수행한다. 새 본 앱의 실제 인증/조회는 기존 검증 앱의 통과와 별개이며 별도 확인이 필요하다.
메일 변경 기능의 실제 사서함 시험은 수행하지 않는다. 사용자가 정한 시험 계정·항목·작업에 별도 승인이 필요하다.
실제 서버의 보존 정책·변경 결과·읽음 확인 미발송은 실환경 시험 전 확정하지 않는다.

## EWS 자동 입력 수정본 (2026-10-19)

최신 실행 파일: `bin/LoginFix/OwaDesktopCleaner.exe` (이전 CredentialLogin 빌드의 종료 오류 수정). 기존 실행 파일이 사용 중이므로 별도 출력 폴더로 빌드했다. 기존 앱을 먼저 종료해야 한다.

- EWS 로그인 정보 버튼에서 저장 값 수정·삭제 가능. 저장은 서버 인증 성공을 의미하지 않는다.
- 로그인/저장 시 이 PC에 저장을 해제하면 기존 저장 항목도 삭제된다. 취소는 입력 변경을 저장하지 않는다. 저장 정보 삭제 버튼은 즉시 적용된다.
- 계정 저장과 자동 로그인 시도(세션 보존)는 별개다. 세션 정리는 저장 계정을 삭제하지 않는다. 계정 삭제는 이미 인증된 세션을 종료하지 않는다. 둘 다 지우려면 저장 정보 삭제 후 로그아웃 · 세션 정리를 실행한다.
- 저장 계정은 지정된 회사 EWS 인증 요청에만 전달하며, 자동 제출하지 않는다. 변경 요청 중 추가 인증이 필요하면 취소하며 변경 요청을 자동 재시도하지 않는다.
- 비밀번호는 PasswordBox에서 마스킹된다. WebView2 API 전달 중 관리 메모리에 일시적으로 존재할 수 있다. 웹 문서/JavaScript에는 전달하지 않는다.

### 사용자 시험 순서
1. 기존 앱 종료 후 위 수정본 실행. 변경 작업 허용은 끈 상태로 둔다.
2. OWA 로그인 → 로그인 완료 · 클리너 열기 → EWS 창에서 계정 입력, 이 PC에 저장 선택, 로그인.
3. 실제 폴더 조회 및 조회만 검색 성공 확인.
4. 로그아웃 · 세션 정리 후 다시 OWA 로그인과 클리너 열기. EWS 인증을 요구하면 두 입력란이 채워지고, 로그인 클릭 후 조회되는지 확인.
5. EWS 로그인 정보에서 수정/저장 또는 저장 정보 삭제 확인. 삭제 후 창을 다시 열면 입력란이 비어 있어야 한다.
6. 취소 시 인증이 제출되지 않고, 저장 옵션 해제 후 로그인하면 다음 창에 저장 값이 남지 않는지 확인.

수정본 검증: 별도 출력 경로 Release 빌드 성공(경고 0, 오류 0). 실제 자격 증명 저장·자동 입력·회사 서버 인증 시험은 사용자 수행 예정. 이번 변경에서 실제 계정 읽기/저장, 실사서함 시험, 배포는 수행하지 않았다.

## 로그인 종료 오류 수정 (2026-10-19)

- Windows Application 이벤트 1026에서 15:46:45/15:47:18의 `CoreWebView2Deferral.Dispose → Complete` COMException 0x8000000E를 확인했다. 명시적 Complete 이후 using 종료의 Dispose가 다시 Complete를 호출하던 중복 완료를 제거했다. 완료는 한 번만 호출하며, 요청 만료 시 발생하는 완료 예외도 해당 인증 경로에서 처리한다.
- EWS 인증 창 표시부터 진행 막대를 보이고, 로그인 제출 후 서버 응답 대기 경과 초를 표시한다. 성공/실패/취소 시 진행 표시를 해제한다. 실제 네트워크 인증 시간을 단축한다고 보장하지 않는다.
- OWA 로그인 기억: 기본 켜짐, WebView2 저장 제안에서 저장을 선택하고 정상 종료하면 다음 실행에 같은 전용 프로필을 쓴다. 앱은 OWA 비밀번호 DOM을 읽지 않는다. 회사 정책/폼에 따라 저장 제안이 제공되지 않을 수 있으며 실제 회사 화면에서 확인이 필요하다.
- 로그아웃 · 세션 정리는 OWA 전용 프로필의 저장 데이터와 세션을 정리하고 OWA 기억 설정도 끈다. 다시 저장하려면 체크를 켠 뒤 로그인한다. Windows 자격 증명 관리자에 별도로 저장한 EWS 계정은 EWS 로그인 정보에서 삭제한다.
- 검증: LoginFix 출력 경로 Release 빌드 성공, 경고/오류 0. 실제 로그인·OWA 저장 제안·종료 오류 재현 시험은 사용자가 수행한다. 실사서함 변경은 수행하지 않았다.

시험: 기존 앱 종료 → bin/LoginFix/OwaDesktopCleaner.exe 실행 → OWA 로그인 기억 체크 확인 → OWA 로그인 및 저장 제안 수락 → 클리너 열기 → EWS 로그인 → 진행 표시와 조회 성공 확인 → 정상 종료 후 재실행하여 OWA 기억 확인.
