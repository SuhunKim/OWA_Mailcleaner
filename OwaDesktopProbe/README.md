# OWA Desktop Probe — 1단계 연결 검증

## 현재 결론 (2026-10-19, KST)

**1단계 연결 검증 통과. 사용자가 제공한 2026-10-19 실제 앱 로그에서 GetFolder/FindFolder/FindItem 모두 HTTP 200 및 SOAP NoError, 폴더 11개 전체 페이지와 메일 메타데이터 5건 조회 성공을 확인했다. 증거 출처는 사용자 제공 로그이며 도구가 직접 수집한 응답은 아니다.**

이 앱은 완성된 메일 클리너가 아니다. 기존 v1.1과 기존 배포본은 수정하지 않았다.
구현 구조·재사용 범위·기능 이식 순서·팀원 배포 준비는 [IMPLEMENTATION-PREP.md](IMPLEMENTATION-PREP.md)에 정리했다. 전체 클리너 UI나 사서함 변경 기능은 이번 범위에서 구현하지 않았다.

## 실행

`bin\Release\net8.0-windows\OwaDesktopProbe.exe`를 실행한다.
동일 폴더의 DLL, probe.js, runtimes 등 파일을 함께 유지해야 한다. EXE 하나만 복사하면 안 된다.

현재 PC: .NET SDK 10.0.402, Windows Desktop Runtime 8.0.32 설치 확인.
앱 대상: net8.0-windows / WPF, WebView2 NuGet 1.0.3537.50.
실제 실행 WebView2 Runtime: 155.0.4283.45.
Outlook 설치, Tampermonkey, Chrome/Edge 확장은 사용하지 않는다.
현재 PC에서 별도 앱 설치나 관리자 승격 없이 앱 실행에 성공했다.
다른 팀원 PC의 런타임 설치 권한/보안 정책과 패키징은 아직 검증하지 않았다.

프로젝트 폴더에서 빌드:
```powershell
dotnet build .\OwaDesktopProbe.csproj -c Release
```
복원에는 NuGet 접근이 필요하다. 최초 개발 빌드에서 .NET 사용자 캐시 초기화 때문에 도구 샌드박스 밖 빌드를 사용했다. 이는 앱 실행에 관리자 권한이 필요하다는 뜻이 아니다.

## 사용 순서

1. 앱 안쪽의 실제 회사 OWA 로그인 화면에 사용자가 직접 로그인한다.
2. OWA 메일 목록이 보이면 상단 `로그인 완료 확인`을 누른다. 이 버튼은 로그인 입력/제출 기능이 아니며, EWS 성공을 뜻하지 않는다.
3. `EWS 폴더 조회`: GetFolder(inbox), FindFolder(msgfolderroot, Deep, 페이지당 100개)를 실행한다. WebView2 기본 인증 창이 뜨면 OWA와 동일한 회사 계정을 직접 입력한다. 사용자 승인으로 추가한 인증 경로이며 앱 코드는 입력값을 받지 않는다. 인증 입력을 포함해 요청당 최대 3분, 조회 전체 최대 4분이다.
4. 성공하면 폴더를 선택하고 `선택 폴더 메일 5건 조회`를 누른다. FindItem으로 제목, 발신자, 수신 시각, 크기, 읽음 여부만 조회한다.
5. 빈 폴더에서 0건인 결과만으로 실제 메일 조회 합격으로 처리하지 않는다.

로그인과 EWS 인증은 별개다. 인증 실패를 같은 계정으로 반복하지 말고 오류와 계정 표기/회사 인증 정책을 확인한다.

## 실제 실행 결과 — 최초 취소 방식과 이후 허용 방식 구분

- 회사 로그인 화면 표시: https://mail.apsfamily.com/owa/auth/logon.aspx
- 사용자가 앱에서 직접 로그인했고 OWA 메일 목록 표시를 확인했다.
- 최초 GetFolder는 15초 뒤 TIMEOUT. 이후 원인 분리용 인증 이벤트 처리를 추가했다.
- 별도 비인증 HEAD에서 HTTP 401, 인증 방식 Negotiate / NTLM 확인. 이 요청은 쿠키/자격 증명을 사용하지 않았다.
- 수정 앱의 동일 WebView2 OWA 출처 fetch에서 추가 HTTP 인증 이벤트 발생.
- 앱은 별도 자격 증명을 수집하지 않도록 추가 인증 요청을 취소했다.
- 17:36:14: WebView2 EWS 실제 HTTP 응답 401, GetFolder HTTP 401, 49ms.
- 17:36:16, 17:36:42에도 같은 추가 인증/401 상태가 앱 기록에 표시됐다.
- 이 시점(추가 인증 취소 버전)에는 GetFolder NoError, FindFolder, FindItem 성공 응답을 확보하지 못했다.
- 초기 “조회 성공” 선택 응답과 당시 앱 기록이 달라 처음에는 미합격 판정했다. 이후 기본 인증 창을 허용한 수정본에서 사용자가 다시 폴더·메일 조회 성공을 확인한 것은 별도 시험 결과다.
- 2026-10-19 재개: 실행 중인 검증 앱 프로세스가 없어 지난 메모리 로그를 복구할 수 없었다. 성공 건수·응답 시각·SOAP 코드 값을 임의로 생성하지 않았다.
- 모의 응답으로 서버 연결 성공을 주장하지 않았다.

최초 실패 결과는 **OWA 세션만으로 EWS가 자동 인증되지 않았다**는 증거다. 이후 사용자가 허용한 기본 추가 인증 경로에서는 사용자가 실제 조회 성공을 확인했다.
추가 인증을 취소했으므로 유효한 별도 NTLM 인증까지 서버가 거부한다고 단정할 수는 없다.
WebView2나 EWS 자체가 불가능하다고 결론 내리지 않는다.

## 인증·데이터 경계

- 회사 HTTPS 출처만 최상위 탐색 허용. 실제 확인한 로그인 리디렉션은 동일 호스트의 /owa/auth/logon.aspx.
- 외부 출처/새 창은 차단한다. 추가 회사 인증 리디렉션이 필요하면 실제 경로를 확인한 후 최소 범위를 추가해야 한다.
- OWA 페이지에서 fetch('/EWS/Exchange.asmx', { credentials: 'include' }) 실행. 로컬 HTML 출처나 별도 HttpClient에 쿠키를 복제하지 않는다.
- 네이티브 호스트 객체/웹 메시지, 개발자 도구, 비밀번호 자동 저장, 자동 완성은 비활성.
- TLS 인증서 검증이나 브라우저 보안은 해제하지 않는다.
- 사용자가 진행한 EWS 조회 중 회사 HTTPS EWS 주소의 추가 HTTP 인증만 WebView2 기본 창에 맡긴다. 요청당 최대 2회이며 범위 밖 인증은 취소한다. 앱은 Response.UserName/Password에 접근하지 않는다. NTLM 비밀번호 수집/자동 제출/Windows 인증 정책 변경 기능은 없다.
- 로그에는 시각, 작업명, HTTP 상태, SOAP 응답 코드, 건수만 표시한다. 비밀번호·쿠키·토큰·메일 본문·메일 제목을 로그 파일에 기록하지 않는다.
- 조회된 메타데이터는 앱 메모리와 표에만 표시한다. 외부 분석 서비스로 보내는 코드는 없다.
- 앱 코드의 EWS 작업은 GetFolder, FindFolder, FindItem뿐이다. UpdateItem, DeleteItem, MoveItem, DeleteAttachment, SendItem은 없다.
- 검증 중 OWA에서 직접 메일을 열지 않는다. 로그인 후 웹뷰는 높이 1로 줄이고 마우스 조작을 막는다. 회사 OWA 자체의 모든 서버 동작을 감사한 것은 아니며, 사서함 전후 비교 감사도 수행하지 않았다.

## 세션 보존/정리

앱 전용 프로필: `%LOCALAPPDATA%\OwaDesktopProbe\WebView2`
일반 Edge/Chrome 프로필이나 인증 정보를 읽지 않는다.

- 기본값: 세션 보존 안 함. 시작 시와 정상 종료 시 전용 프로필의 브라우징 데이터를 정리한다.
- `자동 로그인 시도 (전용 세션 보존)` 선택 후 정상 종료하면 전용 세션을 다음 실행에 재사용한다. 비밀번호를 저장하는 기능이 아니다. 만료/회사 정책에 따라 다시 로그인해야 한다.
- `로그아웃·전용 세션 정리`는 앱 전용 쿠키·캐시·사이트 저장소를 지운 후 OWA를 다시 연다. 회사의 서버 전체 SSO 세션까지 종료하는 기능은 아니다.
- 강제 종료/전원 종료 시 종료 정리는 보장할 수 없다. 기본 모드의 다음 실행에서 다시 정리한다.
- 회사 통합 인증 정책에 따라 세션 정리 후에도 서버가 자동 인증할 수 있다.

## 오류 구분

401: 인증 필요/거부, 403: 접근 거부, 440: 세션 만료.
HTTP 추가 인증 이벤트: 별도 자격 증명 요구를 명시.
HTML 반환: 로그인 페이지 반환. 리디렉션: 재로그인 필요 또는 정책 경로 확인.
NETWORK_ERROR / TIMEOUT: 네트워크 실패 / 제한시간 초과.
EWS SOAP 오류 코드: HTTP 성공과 별도로 실패 처리.
재로그인 버튼은 실제 회사 OWA 화면을 다시 연다.

## 다음에 필요한 결정

OWA + WebView2 기본 추가 인증 경로를 유지해 본 앱을 준비한다. 팀원별 계정 권한, 사내망/VPN, 추가 인증 및 계정 전환은 팀원 인수 시험에서 확인한다. 추가 인증 없이 OWA 로그인만으로 자동 인증하려는 경우에만 회사 Exchange 정책을 별도로 확인한다.

사용자는 2026-10-16에 OWA 로그인 이후 WebView2 기본 추가 인증 창에서 직접 입력하는 방식을 명시적으로 허용했다. 앱 자체 비밀번호 입력 UI, 브라우저 인증 정보 추출, Outlook 의존 우회는 채택하지 않는다.

사용자 확인에 근거한 2단계 구현 준비와 아직 남은 직접 응답 확인/팀원 인수 시험은 IMPLEMENTATION-PREP.md에서 구분했다.
사서함 변경 시험은 별도 사용자 승인 후에만 실시한다.

기존 C# Controls는 net462/net8.0-windows UI 라이브러리이며,
Demo의 폴더와 메일은 하드코딩 샘플이었다. 실제 메일 연결 구현으로 간주하지 않는다.
