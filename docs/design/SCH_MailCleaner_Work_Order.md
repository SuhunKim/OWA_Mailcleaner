## 4. 구현 순서

### 1단계 — 핵심 호출 근거 확보

기존 자료와 실제 로그인된 화면에서 읽음 처리, 휴지통 이동, 휴지통 비우기, 일반 첨부 삭제 기능의 호출·식별자·결과를 확인한다. 추정한 URL/함수명으로 쓰기 기능을 만들지 않는다. 조회 과정에서 메일을 열면 읽음 상태가 바뀌는지도 확인한다. 인증 정보와 메일 본문을 문서·로그에 기록하지 않는다.

첨부만 삭제가 미확인이라면 상태를 명시하고, 독립적으로 구현 가능한 기능은 진행한다. 전체 메일 삭제를 첨부 삭제 대안으로 자동 채택하지 않는다.

### 2단계 — 읽음 처리와 휴지통 이동

목록 선택, 선택 건수·대상 미리보기, 실행 전 확인, 진행 상태, 중단, 건별 결과를 구현한다. 계정·편지함·대상 식별자 일치를 실행 전에 확인한다. 서버 반영 후 재조회하여 결과를 확인한다. 응답이 유실되면 자동 재시도하지 않고 결과 미확인으로 남긴다. 중단은 다음 항목 전송을 멈추되 이미 전송한 항목의 결과 확인과 구분한다.

### 3단계 — 첨부 조회·첨부만 삭제와 휴지통 정리

첨부의 식별값·이름·용량과 본문/메일 자체의 식별값을 구분한다. 메일 전체 용량을 첨부 용량이나 확보 예상 공간으로 표시하지 않는다. 첨부 삭제 후 메일 본문 유지 및 해당 첨부 제거를 재확인한다. 일반 첨부·본문 인라인 이미지·대용량 링크 처리 범위를 근거에 따라 구분한다.

휴지통 정리는 선택 영구 삭제인지 휴지통 전체 비우기인지 실제 사이트 범위를 먼저 확정한다. UI에 그 범위와 되돌릴 수 없음을 표시하고 별도 확인을 받도록 구현한다. 실제 영구 삭제 시험은 사용자가 수행한다.

### 4단계 — 기존 UI 구성과 SCH 색상 적용

작업 루트의 `OwaDesktopCleaner`, `Outlook_Mail_Cleaner_Web` 등 실제 소스에서 사용자의 기존 UI를 확인한다. 어느 화면을 기준으로 했는지 기록한다. SCH 색상은 실제 화면 또는 기존 확인 자료를 근거로 사용한다. 검색 조건·대상 목록·작업 버튼·진행률·결과 영역을 일관되게 구성한다. 빈 목록, 로딩, 실패, 결과 미확인, 버튼 비활성 이유를 표시한다. 다른 프로그램 소스는 수정하지 않는다.

### 5단계 — 검토·사용자 검증·배포 준비

정적 검토 후 사용자에게 정확한 빌드/실행 명령과 시험 순서를 제공한다. 사용자 결과를 반영하여 오류를 수정한다. 기존 README의 publish 명령을 프로젝트 설정과 대조하여 갱신한다. Windows/WebView2 의존성, 로그인, 사용법, 알려진 제한을 포함한다. 최종 실행 파일이 실제 생성·확인되기 전 배포 완료라고 보고하지 않는다.
